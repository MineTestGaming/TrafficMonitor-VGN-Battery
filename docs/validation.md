# 验证记录

日期：2026-11-25。本机 Windows、MSVC 19.51、Windows SDK 10.0.26100.0、x64 Release、静态 C++ runtime。

- 本机宿主：TrafficMonitor 文件版本 1.8.6.0，x64；插件接口固定 API 7。
- 状态测试：0%、100%、非法百分比、未知、断连、超龄、时间异常。
- 协议测试：Evision 请求序号和报文长度；Compx checksum、前导 Report ID、短包、非法电量、真实鼠标电量响应、回报率映射。
- ABI 测试：LoadLibrary/TMPluginGetInstance、单例、索引边界、非空字符串、DataRequired 返回时间、并发 getter、5 次加载卸载。
- helper 生命周期测试：使用真正停留 60 秒的假采集器，验证 DLL 在 30 秒终止其进程，且反复轮询不阻塞；另验证 DLL 卸载立即结束自己的采集器。四项 CTest 均通过（含约 30 秒的超时测试）。
- DLL→helper→设备集成测试：两台在线 2.4G 设备均得到实际百分比，不能用 `--` 通过此测试。
- 实际设备：N75 PRO 2.4G 原始电量 56–57%；R1 SE+ 20%，未充电，CID 2/MID 31，固件原始值 03 00、1000 Hz、DPI 档位编码 2。数据为当时快照。
- BLE：发现配对的两个设备及标准电池服务，但没有活动蓝牙连接，未取得 Uncached 实时电量；旧 PnP 电量没有用来替代真实结果。
- 安装与真实宿主：已将两个运行文件安装到 `C:\TrafficMonitor\plugins`。原宿主权限较高，终端退出被 Windows 拒绝；用户自行正常退出后完成重启。保留原有 `BatteryPowerMon,FxOP34Lm`，追加 `VgnVxeN75Battery,VgnVxeR1Battery`，修改前配置备份保存在本地 `.analysis/trafficmonitor-backup/config-before-install.ini`。
- 真实 TrafficMonitor 生成的最新采集快照返回键盘 56%、鼠标 20%，充电标记均为未充电，回报率 1000 Hz。与独立测试相互印证。
- 任务栏渲染验收：用户确认“任务栏电量显示正常，无需继续界面检查”。界面工具未能枚举该任务栏窗口，因此没有宣称自动截图或自动检查详情对话框成功。
- 充电实测：用户给两台设备插电后，N75 返回电量 59、充电字节 01；R1 SE+ 返回电量 30、充电字节 01，Compx 完整响应 `08 04 00 00 00 02 1E 01 0E 7D 00 00 00 00 00 00 9D` 校验通过。0.1.1 使用此状态将 `%` 换成 `+`，停止充电恢复 `%`。
- 0.1.1 完整 DLL 充电集成测试实际输出 `keyboard=62+ / mouse=30+`，新增充电、充满、空电量、停止充电与过期/断连状态测试通过，四项 CTest 全部通过。用户退出宿主后已安装新版并重启，安装 DLL 与测试构建的 SHA-256 一致。
- 0.1.2 新增 API 7 插件命令“立即刷新”和设置窗口同名按钮。确定性采集器测试验证菜单名/索引、30 秒间隔内提前采集、无效命令不刷新、命令快速返回，以及采集中重复请求合并为一次追加采集。
- 0.1.2 Release 构建与五项 CTest 全部通过（包含约 30 秒的真实 helper 超时测试，总计约 32 秒），独立代码审查未发现阻止提交的问题。官方接口头文件保持上游原样，其中注释已有一处行尾空格；本项目源码与文档的暂存差异空白检查通过。
- 0.1.2 设置窗口使用标准 TaskDialog，按钮保持窗口打开，内容按采集状态更新；无 v6 公共控件时回退为可请求刷新的消息框。独立 UI 验收进程未能在界面工具的可见窗口清单中列出，因此本次不宣称完成自动截图或按钮视觉验收。
